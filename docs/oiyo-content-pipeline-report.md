# OIYO 콘텐츠 파이프라인 및 프로젝트 운영 설계 보고서

작성일: 2026-06-03  
대상: oiyo.net, blog.oiyo.net, wiki.oiyo.net, ahoxy.com, Tistory 채널군

## 1. 요약

현재 계획은 방향이 좋습니다. 핵심은 `oiyo.net`을 단순 테스트 사이트가 아니라 “성격/운세/자기이해 도구를 직접 실행하는 본진”으로 두고, `blog.oiyo.net`과 `wiki.oiyo.net`은 검색 유입을 모아 본진으로 보내는 읽을거리 계층으로 쓰는 것입니다.

추천 운영 원칙은 다음과 같습니다.

- `oiyo.net`: 테스트, 결과, 개인화 리포트, 향후 회원가입/결제의 중심.
- `wiki.oiyo.net`: 짧고 체계적인 지식 문서, 유형별 설명, evergreen SEO 콘텐츠.
- `blog.oiyo.net`: 이미 이전 완료된 읽을거리 아카이브. 앞으로는 크게 수정하지 않고 링크 자산으로 유지.
- `ahoxy.com`: 별도 브랜드/블로그 연결 자산. OIYO와 너무 강하게 섞기보다 필요한 곳에서만 추천 링크.
- Tistory 채널: 대중 트래픽을 얻기 위한 엔터테인먼트/리뷰/밈 채널. 직접 수익화와 OIYO 보조 유입을 병행.

가장 중요한 의사결정은 “MBTI와 애니어그램을 어떤 URL 체계로 oiyo.net 안에 흡수할 것인가”입니다. 제안은 테스트와 위키형 문서를 분리하는 것입니다.

- 테스트: `/ko/mbti/test`, `/ko/enneagram/test`
- 허브: `/ko/mbti`, `/ko/enneagram`
- 유형 문서: `/ko/mbti/intj`, `/ko/mbti/infp`, `/ko/enneagram/type-1`
- 비교/조합 문서: `/ko/mbti/intj-vs-intp`, `/ko/enneagram/type-5-vs-type-6`
- 실용 문서: `/ko/mbti/intj-career`, `/ko/enneagram/type-4-relationship`

## 2. 현재 oiyo-astro 구조 진단

현재 저장소는 Astro 정적 사이트 + React island 구조입니다. `astro.config.mjs`는 `site: https://oiyo.net`, `output: static`, Cloudflare adapter를 사용하고 있어 Cloudflare Pages 무료 운영과 잘 맞습니다.

이미 존재하는 중요한 구조:

- 다국어 라우팅: `en`, `ko`, `ja`, `cn`, `fr`, `es`
- 메인 페이지: `src/pages/[locale]/index.astro`
- MBTI 테스트: `src/pages/[locale]/mbti/test.astro`
- 애니어그램 테스트: `src/pages/[locale]/enneagram/test.astro`
- 테스트 컴포넌트: `src/components/tests/MbtiCareerTest.tsx`, `src/components/tests/EnneagramTest.tsx`
- 온톨로지 허브: `src/pages/[locale]/ontology/index.astro`
- 블로그 외부 링크: `src/config/navigation.ts`에서 `https://blog.oiyo.net` 연결

좋은 점:

- 정적 배포에 적합해서 초기 비용을 거의 0에 가깝게 유지할 수 있습니다.
- React 컴포넌트로 테스트 UI를 구현하고 있어 향후 Next.js로 재이전할 때도 재사용 여지가 큽니다.
- 다국어 메시지와 라우팅이 이미 깔려 있어 한국어 중심으로 시작하되 영어/일본어 확장이 가능합니다.

주의할 점:

- 현재 MBTI/애니어그램은 “테스트 페이지”만 있고, 검색 유입을 받을 “문서형 허브/유형별 페이지”가 아직 부족합니다.
- 홈 화면은 앱처럼 잘 작동하지만 SEO 랜딩 관점에서는 각 테스트의 설명형 콘텐츠가 더 필요합니다.
- `wiki.oiyo.net`이 검색 결과에서 잘 잡히지 않는 것으로 보여, 단순 이전만으로는 색인 효과가 충분하지 않을 수 있습니다.

## 3. 핵심 전략

### 3.1 본진은 oiyo.net

`oiyo.net`은 최종적으로 결제와 회원 기능을 붙일 곳입니다. 그러므로 트래픽과 사용자 행동 데이터는 가능하면 `oiyo.net`에 모아야 합니다.

초기 Astro 단계에서는 다음 기능을 우선합니다.

- 무료 테스트 실행
- 결과 공유
- 유형별 정적 문서
- 관련 테스트 추천
- 애드센스 광고
- Search Console, Analytics, 이벤트 측정

Next.js + Vercel로 다시 갈 때 붙일 기능:

- 회원가입
- 테스트 히스토리 저장
- 고급 결과 리포트
- PDF 리포트
- 결제
- 개인화 추천
- 이메일 리텐션

즉, 지금은 “결제 없는 무료 진단/읽을거리 제품”을 만들고, 나중에는 “개인화 리포트 SaaS/콘텐츠 상품”으로 확장합니다.

### 3.2 wiki.oiyo.net 콘텐츠는 oiyo.net 안으로 흡수

MBTI와 애니어그램처럼 테스트와 직접 연결되는 지식 콘텐츠는 `wiki.oiyo.net`에 계속 두기보다 `oiyo.net`의 하위 경로로 옮기는 것이 좋습니다.

권장 이유:

- 테스트 페이지와 문서 페이지가 같은 도메인 권위를 공유합니다.
- 사용자가 문서를 읽다가 바로 테스트를 실행할 수 있습니다.
- 향후 결제/회원 기능이 붙을 때 이전된 문서가 본진의 SEO 자산이 됩니다.
- Cloudflare Pages에서 정적 문서 대량 생성이 쉽습니다.

권장 처리:

- `wiki.oiyo.net/mbti...`는 `oiyo.net/ko/mbti...`로 301 리다이렉트.
- `wiki.oiyo.net/enneagram...`는 `oiyo.net/ko/enneagram...`로 301 리다이렉트.
- `wiki.oiyo.net`은 한동안 유지하되, 새 글은 `oiyo.net` 중심으로 작성.

단, 위키에 다른 주제의 독립 지식 콘텐츠가 많다면 전부 즉시 흡수하지 말고 “테스트와 연결되는 주제”만 먼저 옮깁니다.

## 4. 콘텐츠 구조 제안

### 4.1 MBTI

MBTI는 검색량이 크지만 경쟁도 높습니다. 단순 “INTJ 특징”만으로는 어렵고, 테스트/비교/직업/연애/궁합/유명인/캐릭터 같은 세부 의도를 조합해야 합니다.

권장 구조:

- `/ko/mbti`: MBTI 허브
- `/ko/mbti/test`: MBTI 직업 적성 테스트
- `/ko/mbti/types`: 16유형 전체 목록
- `/ko/mbti/intj`: INTJ 특징
- `/ko/mbti/intj-career`: INTJ 직업
- `/ko/mbti/intj-relationship`: INTJ 연애
- `/ko/mbti/intj-compatibility`: INTJ 궁합
- `/ko/mbti/intj-vs-intp`: INTJ와 INTP 차이
- `/ko/mbti/e-i`, `/ko/mbti/s-n`, `/ko/mbti/t-f`, `/ko/mbti/j-p`: 지표별 설명

초기 우선순위:

1. MBTI 허브
2. 16유형 기본 문서
3. 16유형 직업 문서
4. 인기 비교 문서
5. 궁합 문서

문서 템플릿:

- 한 줄 요약
- 핵심 특징
- 강점
- 약점
- 일하는 방식
- 연애/관계 방식
- 잘 맞는 환경
- 주의할 오해
- 관련 테스트 CTA
- 관련 문서 링크

주의:

- MBTI 명칭은 상표 이슈가 있을 수 있으므로, 페이지 하단에 “공식 MBTI 진단이 아니며 자기이해용 콘텐츠”라는 안내를 둡니다.
- 가능하면 “MBTI 테스트”보다 “MBTI 성향 테스트”, “MBTI 기반 직업 성향 테스트”처럼 표현을 부드럽게 씁니다.

### 4.2 애니어그램

애니어그램은 MBTI보다 검색 경쟁은 낮고, 깊이 있는 콘텐츠를 만들기 좋습니다. OIYO의 “자기이해/온톨로지” 톤과도 잘 맞습니다.

권장 구조:

- `/ko/enneagram`: 애니어그램 허브
- `/ko/enneagram/test`: 애니어그램 테스트
- `/ko/enneagram/types`: 9유형 전체 목록
- `/ko/enneagram/type-1`: 1번 유형
- `/ko/enneagram/type-1-wing-9`: 1w9
- `/ko/enneagram/type-1-wing-2`: 1w2
- `/ko/enneagram/triads`: 본능/감정/사고 중심
- `/ko/enneagram/wings`: 날개 설명
- `/ko/enneagram/growth-stress`: 성장/스트레스 방향
- `/ko/enneagram/type-4-relationship`: 4번 유형 관계

초기 우선순위:

1. 애니어그램 허브
2. 9유형 기본 문서
3. 날개 문서 18개
4. 성장/스트레스 방향 문서
5. 관계/직업 문서

문서 템플릿:

- 유형 이름과 핵심 문장
- 핵심 욕구
- 핵심 두려움
- 자주 보이는 패턴
- 건강할 때
- 불안정할 때
- 관계에서의 모습
- 일/커리어에서의 모습
- 성장 팁
- 테스트 CTA

### 4.3 온톨로지 허브와 연결

OIYO만의 차별점은 MBTI/애니어그램을 사주, 운세, 취향, 라이프스타일과 묶어 “나를 이해하는 여러 렌즈”로 보여줄 수 있다는 점입니다.

권장 연결:

- MBTI 결과 페이지에서 온톨로지 허브로 연결: “내 성향을 다른 관점에서도 보기”
- 애니어그램 결과 페이지에서 온톨로지 허브로 연결: “핵심 동기와 운의 흐름 함께 보기”
- 온톨로지 허브에서 MBTI/애니어그램 테스트를 주요 진입점으로 배치
- 유형 문서 하단에 관련 테스트 2개 이상 추천

## 5. 도메인별 운영 설계

### 5.1 oiyo.net

역할:

- 제품 본진
- 테스트 실행
- 개인화 결과
- SEO 랜딩
- 향후 결제/회원 기능

콘텐츠:

- 테스트
- 유형별 문서
- 결과 해석
- 성격/운세/자기이해 허브
- 광고 친화적인 evergreen 콘텐츠

관리 방식:

- 매주 신규 문서 5~10개 추가
- 매월 Search Console 기준으로 제목/설명 개선
- 인기 문서는 내부 링크를 계속 보강
- 광고 배치는 사용자 경험을 해치지 않는 위치부터 시작

광고 배치 제안:

- 허브 페이지: 본문 중간 1개, 하단 1개
- 유형 문서: 첫 화면 아래 1개, 중간 1개, 하단 1개
- 테스트 페이지: 시작 전/결과 후 중심. 테스트 진행 중 광고는 최소화
- 결과 페이지: 결과 요약 아래, 관련 문서 위

### 5.2 wiki.oiyo.net

역할:

- 기존 위키 자산의 임시 보관소
- 리다이렉트 출발점
- 본진 이전 전 staging 성격

추천:

- 새 SEO 글은 되도록 `oiyo.net`에 작성.
- 위키의 MBTI/애니어그램은 `oiyo.net`으로 이전.
- 이전된 문서는 위키에서 301 리다이렉트.
- 위키를 계속 둘 경우, `oiyo.net`에 넣기 애매한 짧은 지식 카드나 용어 사전만 유지.

결정 필요:

- 위키를 장기적으로 유지할지, 완전히 흡수할지.
- 유지한다면 어떤 주제만 남길지.

제 의견:

- MBTI/애니어그램은 흡수.
- 위키는 3~6개월 리다이렉트/보조 허브로 두고, 신규 생산은 중단.

### 5.3 blog.oiyo.net

역할:

- 이미 이전된 읽을거리 아카이브
- 외부 유입 보조
- OIYO 본진으로 보내는 링크 자산

추천:

- 큰 수정은 하지 않되, 인기 글 상단/하단에 `oiyo.net` 관련 링크를 넣습니다.
- 새 글 생산은 중단하거나 최소화합니다.
- 광고 수익은 유지하되, 전환 링크를 놓치지 않게 합니다.

링크 예시:

- MBTI 관련 글 -> `https://oiyo.net/ko/mbti/test`
- 성격/자기계발 글 -> `https://oiyo.net/ko/ontology`
- 운세/사주 글 -> `https://oiyo.net/ko/ontology`

### 5.4 ahoxy.com

역할:

- 독립 브랜드/기존 티스토리 연결 자산
- OIYO와 직접 경쟁하지 않는 보조 수익 채널

추천:

- OIYO의 성격/운세 톤과 ahoxy의 주제가 겹치면 선별 링크만 추가.
- ahoxy.com에서 OIYO로 과도하게 링크를 몰아주면 부자연스러울 수 있으므로 문맥형 링크 위주로 둡니다.
- ahoxy는 별도 브랜드로 유지하는 편이 좋습니다.

### 5.5 gopenguin.tistory.com

역할:

- 게임/리뷰 트래픽
- 직접 애드센스 수익
- 대중 검색어 실험 채널

콘텐츠:

- 게임 공략
- 게임 리뷰
- 업데이트 요약
- 구매/설치/설정 가이드
- 유저 반응 정리

OIYO와의 연결:

- 성격 테스트와 직접 연결하지 않는 것이 좋습니다.
- 예외적으로 “게임 직업 추천”, “플레이 스타일 테스트”, “RPG 성향 테스트” 같은 글에서만 OIYO 테스트로 연결합니다.

### 5.6 jjaltheqoo.tistory.com

역할:

- 연예인 사진, 리뷰, 밈, 유행어 유래 등 빠른 트렌드 트래픽
- 광고 수익 중심

콘텐츠:

- 밈 유래
- 유행어 뜻
- 연예인/인플루언서 이슈 정리
- 짤 모음
- 커뮤니티 반응 요약

OIYO와의 연결:

- “아이돌 MBTI”, “연예인 MBTI”, “캐릭터 성격 유형” 글에서만 OIYO MBTI 허브로 링크.
- OIYO는 진지한 자기이해 브랜드로 남겨야 하므로 자극적인 글에서 직접 과하게 연결하지 않습니다.

## 6. 내부 링크 설계

### 6.1 oiyo.net 내부 링크

모든 문서는 다음 링크를 가져야 합니다.

- 상위 허브 1개
- 관련 테스트 1개
- 같은 카테고리 문서 3~5개
- 다른 렌즈 문서 1~2개

예시: `/ko/mbti/intj`

- 상위: `/ko/mbti`
- 테스트: `/ko/mbti/test`
- 관련: `/ko/mbti/intj-career`, `/ko/mbti/intj-relationship`, `/ko/mbti/intj-vs-intp`
- 다른 렌즈: `/ko/enneagram/test`, `/ko/ontology`

### 6.2 허브 페이지 구조

허브 페이지는 단순 목록이 아니라 검색 의도를 흡수하는 관문이어야 합니다.

MBTI 허브 구성:

- MBTI란 무엇인가
- 16유형 빠른 목록
- 무료 테스트 CTA
- 유형별 특징
- 직업/연애/궁합/비교 카테고리
- 자주 묻는 질문

애니어그램 허브 구성:

- 애니어그램이란 무엇인가
- 9유형 빠른 목록
- 무료 테스트 CTA
- 날개/중심/성장 방향
- 유형별 관계/직업 문서
- 자주 묻는 질문

### 6.3 외부 채널 상호링크

권장 링크 방향:

- Tistory -> oiyo.net: 선별적으로, 문맥에 맞게
- blog.oiyo.net -> oiyo.net: 적극적으로
- wiki.oiyo.net -> oiyo.net: 리다이렉트 또는 강한 안내
- oiyo.net -> blog.oiyo.net: 필요한 참고 글에만 제한적으로
- oiyo.net -> Tistory: 거의 하지 않음

이유:

`oiyo.net`은 제품 본진이므로 트래픽이 밖으로 빠지는 링크를 최소화합니다. 반대로 블로그와 티스토리는 검색 트래픽을 본진으로 보내는 보조 채널로 둡니다.

## 7. SEO 운영 체크리스트

### 7.1 기술 SEO

- `sitemap.xml` 자동 생성 확인
- `robots.txt` 생성
- canonical URL 확인
- 다국어 페이지의 `hreflang` 적용
- 404 페이지 생성
- 리다이렉트 규칙 정리
- Open Graph 이미지 준비
- 문서별 title/description 고유화
- JSON-LD 적용: FAQPage, BreadcrumbList, Article, WebApplication

### 7.2 콘텐츠 SEO

- 제목은 검색어와 명확히 맞춥니다.
- 첫 문단에서 답을 바로 줍니다.
- 긴 글은 H2/H3로 촘촘히 나눕니다.
- FAQ를 하단에 둡니다.
- 테스트 CTA는 상단/중간/하단에 배치합니다.
- 같은 유형 문서끼리 링크를 촘촘히 연결합니다.
- “전문 진단 대체 아님” 안내를 둡니다.

### 7.3 색인 전략

초기에는 한국어부터 완성합니다.

1. 한국어 MBTI/애니어그램 허브와 핵심 문서 완성
2. Search Console 등록
3. sitemap 제출
4. 색인 누락 페이지 점검
5. 영어/일본어 확장
6. 중국어/프랑스어/스페인어는 품질 검수 후 공개

다국어를 너무 빨리 노출하면 얇은 번역 페이지가 대량으로 생겨 품질 신호가 약해질 수 있습니다. 한국어를 먼저 단단히 만드는 것이 좋습니다.

## 14. 리스크와 대응

### 중복 콘텐츠 리스크

위키와 oiyo.net에 같은 문서가 동시에 남으면 중복 신호가 생길 수 있습니다.

대응:

- 이전 후 원본은 301 리다이렉트
- 불가피하면 canonical 지정

### 얇은 다국어 페이지 리스크

기계 번역에 가까운 다국어 문서를 대량 공개하면 품질이 낮아 보일 수 있습니다.

대응:

- 한국어 우선
- 영어/일본어만 먼저 확장
- 나머지는 품질 검수 후 공개

### 테스트 신뢰도 리스크

MBTI/애니어그램은 재미와 자기이해용이지만, 사용자가 과도하게 진단처럼 받아들일 수 있습니다.

대응:

- 페이지 하단에 안내 문구
- 결과 문구는 단정 대신 경향으로 표현
- 전문 상담/진단 대체 아님 명시

### 브랜드 분산 리스크

oiyo, blog, wiki, ahoxy, Tistory가 모두 연결되면 브랜드 중심이 흐려질 수 있습니다.

대응:

- `oiyo.net`을 본진으로 선언
- 외부 채널은 유입 보조로만 사용
- 본진에서 외부로 나가는 링크 최소화

## 15. 최종 권장안

가장 좋은 실행 방향은 다음입니다.

1. MBTI와 애니어그램은 `wiki.oiyo.net`에서 `oiyo.net`으로 옮깁니다.
2. `oiyo.net`에는 테스트뿐 아니라 허브/유형/비교/직업/연애 문서를 만듭니다.
3. `wiki.oiyo.net`은 리다이렉트와 보조 용도로 줄입니다.
4. `blog.oiyo.net`은 기존 아카이브로 두고, 인기 글에서 OIYO 본진으로 링크합니다.
5. Tistory 채널은 직접 광고 수익 채널로 운영하되, 문맥이 맞는 글에서만 OIYO로 연결합니다.
6. 초기에는 Astro + Cloudflare Pages로 비용을 낮추고, 유료 리포트 수요가 생기면 Next.js + Vercel로 재이전합니다.

한 문장으로 정리하면, OIYO는 “무료 테스트와 읽을거리로 유입을 만들고, 개인화 리포트로 결제 전환할 수 있는 자기이해 플랫폼”으로 키우는 것이 가장 좋습니다.
