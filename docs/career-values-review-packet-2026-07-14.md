# Career Values 18문항·6차원 사람 검수 패킷

## 현재 판정

- 제품 상태: `reflective-framework/draft`
- 배포 상태: `deployed-draft-noindex` — 2026-07-14 20:01:37 KST부터 GA4 관찰 중
- 검색 상태: `ko`, `en`, `ja`, `zh`, `fr`, `es` 모두 `noindex`, sitemap 제외
- 시행본: `career-values-oiyo-18-v1`
- 구성: 18문항, 6차원, 차원당 3문항, 1–5 중요도 응답
- 결과 용도: 현재 중요하게 여기는 업무환경 조건을 정리하고 확인 질문을 만드는 자기성찰
- 금지 용도: 심리진단, 직업 적합도, 특정 직업 추천, 채용·배치, 사람 간 우열, 인구 백분위, 언어·국가 간 비교

현재 6개 언어 문구는 구현 정합성을 위해 작성된 제품 초안이다. 영어 fallback은 제거됐지만, 어느 locale도 사람 번역·문화 검토가 완료됐다고 주장하지 않는다. locale별 검수 기록과 승인 없이는 `reviewed`로 승격하지 않는다. 또한 `zh/fr/es` indexability는 사람 검수와 별개인 패밀리 전역 비색인 실험의 4~8주 판정을 따른다.

## 1. 실행 정본

| 차원 | item ID | 의도한 내용 |
|---|---|---|
| 안정성 / Security | q1–q3 | 고용 안정, 예측 가능성, 지속 가능한 조건 |
| 성취 / Achievement | q4–q6 | 목표, 도전, 진척과 결과 확인 |
| 자율성 / Autonomy | q7–q9 | 방법·시간·과정·판단의 재량 |
| 기여 / Contribution | q10–q12 | 사람·사회·공동체에 주는 효익 |
| 창의성 / Creativity | q13–q15 | 새로운 아이디어, 다양한 해결, 창작·표현 |
| 인정 / Recognition | q16–q18 | 책임·기여·성장의 공정하고 가시적인 인정 |

각 차원의 원점수 범위는 3–15이며 화면에서는 `(원점수 - 3) / 12 × 100`으로 0–100에 선형 변환한다. 이 값은 백분위, 정확도, 규준 점수, 능력 점수가 아니다. 동점 차원은 선언 순서로 임의 절단하지 않고 모두 공동 상위군으로 보여 준다.

## 2. 개념·문항 내용 검토

| 기준 | 확인 질문 |
|---|---|
| 관련성 | 의도한 차원을 직접 다루는가? |
| 구별성 | 다른 다섯 차원이나 흥미·능력·성격·현재 직무만족과 불필요하게 섞이지 않는가? |
| 단일성 | 한 문항에 두 개 이상의 조건을 동시에 묻지 않는가? |
| 응답 가능성 | 고용 경험이 적거나 없는 사람도 중요도를 판단할 수 있는가? |
| 시간·상황 범위 | 현재 중요도인지 이상적 희망인지 문맥이 일관적인가? |

## 3. 결과·업무환경 예시 검토

결과 설명은 특정 직업 목록을 제시하지 않는다. 다음 세 층만 허용한다.

1. 차원에 대한 중립적 설명
2. 살펴볼 수 있는 업무환경 특징
3. 실제 채용 공고·면담·업무 경험에서 확인할 질문

locale별로 아래를 확인한다.

| 검토 항목 | 통과 기준 | 판정/메모 |
|---|---|---|
| 상위군 제목 | “당신에게 맞는 직업”이 아니라 현재 상위 가치군 |  |
| 업무환경 예시 | 계약·일정·재량·피드백·사명·인정 구조 등 확인 가능한 조건 |  |
| 직업 단정 | 특정 직업, 산업, 전공을 적합/부적합으로 선언하지 않음 |  |
| 점수 의미 | 백분위·진단·능력·안정적 성향으로 오해시키지 않음 |  |
| 동점 | 공동 순위라는 의미가 자연스럽게 전달됨 |  |
| 면책 | 비검증 OIYO 원작성 자기성찰 도구임이 분명함 |  |
| 중요 결정 | 흥미·역량·건강·소득·기회·노동시장 정보도 함께 보도록 안내 |  |

## 5. 짧은 인지 검토 프로토콜

각 locale의 대상 사용자에게 다음을 묻는다.

1. 이 문항이 무엇을 묻는다고 이해했나요?
2. 답할 때 현재 직장, 이상적인 직장, 직업 이름 중 무엇을 떠올렸나요?
3. 인접 응답 옵션의 차이를 어떻게 정했나요?
4. 두 가지를 동시에 묻거나 답하기 어려운 문항이 있었나요?
5. 결과가 직업 추천, 능력 점수, 사람 간 순위처럼 느껴졌나요?
6. 업무환경 예시를 실제 공고나 면담 질문으로 바꿀 수 있었나요?
7. 동점 결과와 0–100 점수의 의미를 어떻게 이해했나요?

중요한 오해가 발견되면 문구를 수정하고 수정본으로 다시 확인한다. 참여자의 원응답, 자유서술, 이름·연락처를 git, GA4, localStorage, company-brain에 저장하지 않는다.

## 6. 분석·데이터 경계

- 프로덕션 GA4에는 `test_started`, `test_completed`, `share_click`과 안정된 `test_id`, `instrument_version`만 보낸다.
- 원응답, 차원 점수, 결과 라벨, 자유서술, 사용자 식별자는 GA4 payload에 넣지 않는다.
- 프로덕션 local result에는 결과 요약만 저장하며 원응답을 저장하지 않는다.
- 7일 관찰은 실제 프로덕션 배포 시각부터 계산한다. 구현일이나 QA일로 소급하지 않는다.
- 표본이 적거나 이벤트가 0인 기간에는 전환율 결론을 내리지 않는다.
- 심리측정 타당화·규준화가 없는 현재 버전으로 신뢰도, 규준, 언어 간 비교를 주장하지 않는다.

## 7. 승격 결정표

| 단계 | 필요한 증거 | 자동 승격 |
|---|---|---|
| draft 유지 | 자동 회귀·빌드·noindex/sitemap 감사 | 가능 |
| locale reviewed | 해당 언어 원어민, 내용 전문가, 대상 사용자 검토와 수정 기록 | 금지 |
| 제한적 indexable | reviewed locale, 명시 책임자 승인, 검색 스니펫·schema 검토 | 금지 |
| 전 locale production | 각 locale 독립 승인, GA4 관찰 계약 충족, 최종 릴리스 QA | 금지 |

일부 locale만 승인될 경우 release gate, plugin locale status, robots, sitemap, hreflang을 같은 변경에서 일치시켜야 한다. 한 locale의 승인을 다른 locale에 전파하지 않는다.
